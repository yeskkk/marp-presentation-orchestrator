# 问题诊断

## 1. 用途与范围

普通有界诊断解释给定现象；返修前诊断展开用户指出的问题族以供确认。
两者采用 [相应模式](references/modes.md)，不是直接修改源码或运行状态的授权。
使用已经建立的 TASK 理解，并以本次问题、目标和证据范围为界，不自动检查整套课程。

## 2. 建立事实

先描述能在源稿、资料、图示或报告中复现的现象，再提出原因。
数学含义错误、表示错配、教学信息不足、工具拒收和执行状态不明具有不同证据来源，
不能从一个层面的失败直接推断另一个层面也错。未读目标只能标为可能，不填假页位。

## 3. 选择诊断方法

数学问题先确定对象、条件和结论，采用适用的复算或反例；教学问题描述学生必须自行
补上的认识以及它对目标的影响；表示问题核对数学定义与实际资产；工具问题定位
最小输入及真实错误。存在多种可能原因时列出能区分它们的最小补证，不先扩大整个项目。
方法服务当前问题，不将一次事故中有效的检查固定为所有诊断的必走步骤。

## 4. 形成有界建议

区分主因、次生表现和相似风险，说明已观察范围、可信度与尚未排除的解释。
修正方向要能回答原问题，并指出不应误伤的正确条件、必要来源与有效内容。
缺资料或权限时说明所需材料及为何需要，不自行增加范围、模型或工作轮次。

## 5. 输出与交接

按 diagnosis-result 交 hypotheses、证据页、confidence 和允许的 recommended_action。
返修前额外给 expansion：表现形式、相关问题、识别方法、修改方向、非目标与验收依据。
这是给用户判断的提案，不声称已经修好或已经同意；工作结束不自动转成 author。

## 不制造可避免的阻塞

先区分必需输入真正缺失、工具能力缺口与误读授权。冻结参考只读不取消 TASK 已授权的
输出副本执行；编拟生活算例没有来源不算资料缺口。不得因程序字段/引文格式拒收要求模型
盲重试，优先主代理使用已保存原响应确定性修正与重放，真实语义缺口不能伪造通过。
