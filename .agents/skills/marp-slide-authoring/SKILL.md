# Marp slide authoring

- Use one `---` separator outside fenced code for each slide.
- Put global directives only in canonical frontmatter.
- Every slide has an invisible stable `slide-id` and a `core` or `support` class.
- A title is optional. Use one only when it helps orientation; reject slogans, vague abstractions, and filler headings.
- Ordinary consecutive exposition may depend on neighbouring slides. Strong local self-containment is required at unit openings, after activities, on example continuations, and where assumptions or objects can be confused.
- Reuse one concrete object across a cluster of related terms when that reduces decoding cost.
- Before a summary slogan, state the object, space, dimension, condition, quantifier, unit, or causal link.
- A calculation page explains why that method is used and what the result means.
- Prefer native text, formulas, Markdown tables, theme CSS, and simple SVG. Never simulate a normal table with a plotting package.
- Course units contain 2–3 multiple-choice prompt/answer pairs; academic reports are exempt. Each question tests fresh inference about a counterintuitive conclusion or error-prone condition.
- Prompt and answer occupy adjacent slides and are linked reciprocally in the manifest.
- Use only local images with teaching purpose and source record. GeoGebra resources are optional ordinary hyperlinks to verified `geogebra.org/m/...` materials.
- Output is PDF only. No persistent HTML, screenshots, contact sheets, or model vision.
