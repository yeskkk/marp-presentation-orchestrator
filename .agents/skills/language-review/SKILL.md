# 语言与术语表达审核

## 1. 目标和范围

判断学生能否从实际语言中准确理解当前对象、条件、关系和任务，检查语言是否真正向学生说话。
不仅找错字，也检查表达是否明白晓畅、自然连贯、符合本学科正常说法。系统性晦涩、干硬名词堆叠和异域措辞替换不能一概以个人文风偏好豁免；不追求文学装饰或单纯缩短。
数学真实性主要由 domain 通道核验，学习路线主要由 pedagogy 判断；本通道发现含义受损时
必须指出，但不假装做完所有复算或据此重新设计课程。

## 2. 输入与基准

沿用已读 TASK 中的受众、教学取舍和术语约定，确认当前冻结稿及本轮范围。
完整阅读正文和相关图注、表头、任务说明，必要时查允许的资料以确定标准名称和使用语境。
不以作者已检查语言的声明替代阅读，也不以机械格式合格推断句义明确。
已确认的专用称谓可以保留，但要判断读者是否知道它指向什么，不能任意发明同义名称。

## 3. 概念词汇与符号

核对同一概念是否持续用同一规范名称，不同概念是否被模糊地合并。
检查符号首次出现的说明、读法、对象类型和跨页指向；省略与缩写是否有清楚依据。
类比、口语解释与正式术语应分工明确，帮助理解但不能取代准确含义或隐去必要条件。
不要机械替换某个正式词汇以显得亲切。指出问题时说明词义或指向如何误导，而非仅说不够口语。

## 4. 句义、逻辑和指代

逐段核对谁在做什么、关系作用于什么对象、前提与结论的范围、量词与否定是否恰当。
连接词所表达的因果、递进、等价或对比应与实际论述一致，不能靠过渡套话掩盖断层。
代词、此处、上述等回指要能定位；跨页引用不能迫使学生猜测被指代的对象。
检查一个句子是否装入过多条件或相互独立的动作，必要时建议拆分并保留数学含义。

## 5. 学生口吻与信息价值

标题可有可无；没有帮助时建议删除而非另造一句，规范概念名可以保留。结论应给具体认识而非过程口号。独立句子应分别起行，但长句可以自然折行；不把文章拆成缺乏承接的碎片。
备课字段、制作状态和合规声明不应直接投影。采用删除反事实判断冗余，不用教学相关等标签保护空话。
必要模型条件、证据说明与来源归属影响理解，应保留或直接重写，不能按关键词清扫。
免责声明需回应当前确有的歧义；引文需要解释它与当前对象的关系，不能孤立堆积。
建议应改善学生能读懂的含义，不替作者添加更多表明遵守要求的文字。

## 6. 表达组件之间的对应

题干、表头、图注、坐标含义和正文应使用一致名称与单位，清楚区分学生需要做的事和已经给出的信息。
答案、提示的措辞不能在题目阶段提前泄露目标判断。标点、括号和数学行间的文字
应帮助学生辨别关系与层次；视觉边界由主题负责，不能建议用空格和样式掩盖不清楚的语义。

## 7. 结果形式与分级

对具体片段说明含义、歧义或注意力损失，给可执行的改写方向；只有必要时提供简短替代表述。
不整稿代写，不对同一原则的所有细微差别制造重复 findings。按是否改变含义和妨碍理解
选择 critical、major、minor，而不是按不符合个人文风分级。
输出当前 review-result 与真实页位证据；issue 需要对应 finding。只读审核，不改原稿，
不把之后作者的修改作为本通道自动追加验收的理由。

### 问题与覆盖的关系

一个问题只描述一次。反馈或返修范围中的同一问题使用当前请求协议的 finding_refs 引用，
不要在多个数组反复写同一段判断。引用不能替代缺失的判断，也不能借引用声称某条要求已经满足；
满意判定仍需准确的本稿证据。程序负责保存和汇总，不要求模型模拟数据库搬运。
