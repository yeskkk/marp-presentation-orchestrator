# 专项审核：一个通道、完整证据、可执行发现


## 1. 范围与独立性

本次 channel 由运行器确定。读取完整冻结稿及相关允许证据，不只看认为有关的几页，
不读取别的 reviewer 结论，不修改稿件。只承担一个主通道，不把五个角色的清单全执行一遍。
共同边界见 [learning-contract](../_shared/learning-contract.md)；选定通道细则见
[channels](references/channels.md)，运行器只注入本通道段落。

## 2. 判断顺序

先确认本次证据修订及范围，再看概念/叙述/图示在实际页上的表现。
历史反馈是要检查的问题，不是作者“已完成”的证明；机械成功也不证明数学、教学或阅读价值。
发现可能问题先核对上下文和条件，避免把正确模型限制误报成废话，或把读不懂的正确公式随意改错。
对资源清单中的图/出处，按需要实际读取；没有读取不得宣称验证过。

## 3. finding 写法

输出严格是 message、slide_ids、severity。finding_id/身份/时间/状态由程序生成。
message 写“具体片段或对象 → 为什么影响学习/结论 → 可执行修正方向”；不用只说“不够直观”。
minor 是局部清晰度，major 是明显妨碍目标理解或正确性，critical 用于严重错误结论等高影响问题。
不为了凑数量报问题；确未发现可 findings: []，但真实反馈与阅读范围仍须回应。
不要添加 schema 不接受的 title/quote/recommendation 字段，把必要内容组织进 message。

## 4. 模型结果与生产事实

feedback_checks 用当前 id/version 和真实原文；issue 同时给可路由 finding，不放任问题在汇总消失。
本任务未渲染/工具缺失不是你可以自填“通过”的事项。只读源稿、提供的文本/结构证据与允许资产；
不截图、OCR、模型视觉查 PDF，也不为排版建议作者改 CSS 或使用 HTML。
review-first 的旧发布证据可能不符合当前源码规约，应指出问题而非先改原稿。

## 5. 修复不是本次工作

首次审核后作者自己改并复算，程序跑机械门禁；不新增 reviewer 验修循环。
若本次是用户确认的重新审核旧发布稿，属于新的明确返修范围，不是私自追加一轮。
只用本轮结果；不能把上一轮 addressed 或作者 readback 当成本轮已无问题。
