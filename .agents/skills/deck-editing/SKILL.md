# 整稿编辑与作者修订

## 1. 本次工作模式

依据 kind、机械问题、submission_correction 和 repair_scope 识别任务。
首次整编改善课次之间的连续性；审后修订处理本轮 findings；机械纠错解决已知拒收原因；
用户返修只覆盖确认的问题族和目标稿件。运行器选择 [对应模式](references/modes.md)，
这些分支不是必须依次执行的四轮编辑。沿用当前会话的 TASK 理解，不重复初始化任务。

## 2. 基线与修改范围

以本次准备的可写副本为起点，历史发布和冻结内容只作证据。已存在的部分修订不能被
原始稿覆盖。完整阅读正文，按判断需要读取相关图示、资料与本轮问题，不照抄作者自评。
识别当前范围、有效用户意见和未解决的语义冲突；不能以提升质量为由改未指定的课件。

## 3. 整体阅读与取舍

先沿学生学习路线读整稿，再判断概念引入、解释、例子、图示与练习是否形成递进关系。
检查跨课术语、符号和已有知识接口；合并重复解释但保留必要的复习与不同情形辨析。
按教学目标和证明深度取舍，不把所有正确段落都当成必须保留的内容。
应用学习损失删除反事实，区分真实数学条件和制作者回执。现实材料必须进入解释，
图示必须表达当前数学关系，不能通过增加“已满足要求”的页内文字应付反馈。

## 4. 修订方法与自检

逐条先还原原问题，再独立判断建议是否正确，最后确定最小且充分的改动。
一个修正可能影响后面的符号、算例或总结，要检查这些依赖；反之不能用不相关改动回答原问题。
对变更选择数学上适用的独立复算，对内容删改核对解释是否断裂，对资产修改重新生成并验算。
未能解决时描述剩余原因和所需决定，不把有疑问的建议照抄成定论。

## 5. 页面结构与保留关系

通常保留已有 slide ID。只有确认允许结构调整时，才在指定范围删除或合并整页，
为每个消失的原 ID 记录理由及实际存在的合并目标；没有消失的页不整批重编号。
映射累计对应返修基线，后续机械修正不能忘记已完成的删并。
内容不适合当前容量时调整内容组织；主题缺陷交项目维护，不以作者样式修补工具。

## 6. 结果和结束边界

按 author-result 提交源码、资产和真实 summary。本轮 finding 对应 resolutions，
确认问题族对应 repair_checks，已授权结构变化对应 slide_changes。
处置说明写清原问题、具体变化、作者如何核验和仍存在的限制，不用同一句完成声明覆盖所有问题。
addressed 仅代表作者处置；程序继续执行机械检查，不增加 reviewer 验修轮次。

## 页数与检查的责任

按获批内容范围写作，预计稿件规模不超过100页。运行稿121–130页的warning提示需在交付前调整到120页内；
超过130页要回到内容范围或拆分方案，不能缩字或更改项目主题。旧发布稿不自动被拆分。
程序保存warning并随交付导出；不用在学生页写“已检查”。warning不是用户待批准事项，
明确的数学、资源或源码错误仍必须修正，工具未完成也不等于通过。

## 练习单页与编拟算例

执行共享 exercise-self-containment 规则：所有要求学生独立作答的题及全部子问在本题页
给足必要信息，答案可另页。一页放不清时换题或简化，不能拆题干或缩字。教学/学生审核
隔离题页作充分性判断，编辑修改题设时同步复算答案和图示，不用旧审核结论冒充新规则通过。
生活算例允许编拟/简化，用自然题设给数学条件、单位和模型关系；不因缺新闻来源提出问题。
只报告具体数学错误、情境不合理或影响理解的条件缺失。
