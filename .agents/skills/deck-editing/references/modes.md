# 编辑模式（由运行器选段；不是全部同时执行）

## integration

### 组装后的首次整稿编辑

从组装好的课次内容出发，先看课程顺序和前后课接口，再查术语/符号/例题重复。
本模式不是审核 finding 修复：不要编造 finding_id，也不替 reviewer 宣布通过。
删重复句、补必要过渡、把定义/例题/图示接成一条学习路线；不要把每课重新写长来体现工作量。
每课首尾说明具体数学问题，先修字段改为实际回顾问题，补充安排仍留在教师计划。
完成时 summary 说明真正调整的衔接，未决资料放 open_questions。保留原页 ID和项目主题。

## revision

### 五通道首次审核后的作者自修

逐条读取本轮 finding 的 message/slide_ids 与原稿，先判断指出的数学或教学关系，再修改。
不要只凭编号写回复，也不要把 reviewer 建议当真理。对方程改动代回原题，对图示改动重算。
每条 resolutions 的 explanation 说明“原问题是什么、在哪些页、改了哪个对象/表达、怎样自查”。
例如原问题是参数化式错误，就应解释修正特解与方向向量，不能回复“另页增加了 EIA 来源”。
无法合理解决标 needs_decision，不能让 explanation 漂到无关页；缺少原证据时不宣称已修好。
不另派 reviewer 验修。所提交的是作者处置，程序只验证结构、规约与机械检查。

## correction

### 已知机械失败／完成结果被拒后的有限纠错

读取具体错误、失败页与当前副本。仅修这些源规约/排版容量/结果字段问题及必要邻页。
源码失败不意味着课程范围变了；不要重新写整课、降低模型或删掉数学含义。
内容太满可拆句/推导/表格；不缩字、改 theme、内嵌 HTML 或复制旧豁免。
若仍带本轮 findings/repair_scope，保留有效 resolutions/repair_checks 和累计 slide_changes；
不能因为这次主要修机械问题而丢掉前次语义修改。工具缺失或检查器疑错给精确事实，不伪造成功。
只有任务已允许的自动恢复由 runner 执行，模型不自行加次数或编辑数据库。

## repair

### 用户确认的指定稿件返修（附加范围，不是额外审核轮）

读取精确用户原话、确认版本、variants/related_problems、non_goals、验收与目标范围。
review-first 从原发布稿＋本轮 findings 开始；edit-first 先按确认问题族改稿。
两者不混合，不重写未指定课件；对问题族在选定稿件的不同表现积极排查，不只改用户举的那页。
每种问题给 repair_checks（addressed/not_found/needs_decision）和实际页。允许删/并时，
每个消失原页给 delete/merge 及理由，合并目标必须实际存在，映射累计对应原返修基线。
删除参考清单页不意味着删除事实必要出处；移走先修表不意味着忽略学生基础。
新稿通过机械门禁后交付并恢复原暂停，不自行开启 p02，也不声称原历史稿已被修改。
