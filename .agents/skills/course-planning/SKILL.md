# 课程规划：把用户需求变成可写的课次


## 1. 何时使用、何时结束

用于新课程规划、用户明确改变教学范围，或旧计划导入后缺少语义 brief。
延续同一已确认任务不是重新规划；已经发布的某稿改良走返修，不另生成整套课次。
只产出可以确认的语义计划，不能自行确认。main 独占顶层 TASK.md 的整理；delegated planner
只提供本次指定范围的建议。没有理由长期保留一个规划会话承担巡检。

## 2. 先消解要求，不把备课表投影出去

读取实际任务、可访问资料和历史反馈；共同边界见 [learning-contract](../_shared/learning-contract.md)。
区分：学生要掌握的数学、教师的课程安排、用户的执行选择。
特别核对“少证明/数学兴趣低”与“保留正确证明”的冲突；准确术语不授权加证明训练。
保留旧计划中仍有效的教学偏好，退休旧执行规则时不能一起丢掉；有歧义指出原句，不伪造已澄清。

## 3. 写课次 brief 的顺序

先给学生会关心或能操作的问题，再确定规范概念/条件。选择一个能复算的例题，说明从哪一步
看见概念。安排必要的几何观察和现实解释；最后给真实易错点、诊断题与补充边界。
这些是 brief 的内容维度，不要求六份表单或固定六页。

按“第几节课”而不是教材章名排；相邻课说明已知什么、这课新增什么。40分钟课可准备约60分钟，
后段用可跳过的例题补充，不把全部讲完当目标。不把“核心40分钟/先修”原样作为学生页面。
通常每课2—3组诊断题，题目和后置答案分开；选择题的迷惑项要有真实误解，不只是换数字。

## 4. 案例与资料准备

现实材料先说明将在哪里参与变量、模型或解释，不能只让后续作者补一页有年份的新闻。
需要真实事实就提供已核验日期和来源位置；资料不可用时列明确缺口，不能编造文件路径。
几何图要描述数学对象与观察目的，不规定像素位置、CSS 或局部字号。
教材摘录的内部行号用于备查，不成为学生“参考文献阅读页”。

## 5. 示例：同一个数学目标的两种 brief

不合适：“目标：定义解与解集，分别论证存在性唯一性。先修二元一次方程。保留全部证明。”
这混合了教师字段、数学要求和未经确认的证明取向。

合适：“让学生找同时满足两个条件的一组数；用代回原式理解解，用两条直线公共点区分
无解、唯一解、无穷多解。引例中的变量有单位，但引例不是概念唯一应用。先做一个共同解判断题，
再给图形解释；本课不做形式证明训练，补充部分比较一组矛盾条件。教材摘录见本课 sources。”
前提是少证明与补充范围确实已获用户确认，而非规划者强塞自己的偏好。

## 6. 输出与交接

按 plan schema 给 presentations/units：id、title、brief、sources，必要时 teaching。
不要另加 schema 未支持的“进度、审核、模型、stage”字段。总体边界进 TASK，课次细节在 task.yaml
一处维护，不把同一 brief 复制成多份合同。程序生成 job ID；不是规划 AI 手拼 assignment ID。
提交前确认每课有入口、数学所得、资料可达、例题可算和明确边界，并把仍需用户决定的冲突单独说清。
