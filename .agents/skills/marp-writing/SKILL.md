# 单课写作：把本课 brief 变成学生能学的内容


## 1. 输入与输出边界

从本课 brief、获准摘录、teaching_context、historical_feedback 和已有内容出发。
共同边界见 [learning-contract](../_shared/learning-contract.md)；包内已注入的段落不重复加载。
run 之前的 brief 只回应如何应用反馈，不写课件。run 输出实际 presentation.md、必要资产和
author-result；theme.css 由 runner 提供，只读。不要生成 SELF-CHECK 或把生产回执放学生页。

## 2. 先搭学习路线，再写满页面

先写学生面临的具体问题与完成后的认识，随后让例子引出概念；不要把一种充电案例写成
“建立方程组只有这种方式”。先修留在备课层，需要旧知识就设置可回答的回顾问题。
一页承担一个可说明的学习动作：看条件、做一步计算、比较两种情况、解释图或诊断误解。
题干先出现，提示/答案另页后置；不在题目页的标题/脚注提前泄露答案。

## 3. 数学写法与作者自检

第一次出现用规范术语并说明含义；符号含义、对象和维度保持一致。直观比喻跟随数学，
不能用绰号替代定义；按确认的证明深度解释，不为“严谨”保留所有证明。
对关键结论用小例子、代回、极端情况或逆向检查自行复算，而不是相信排版正确。

例如 $x+y=2$ 的解可写 $x=2-t,y=t$，向量式为 $(2,0)+t(-1,1)$。
代入 $t=0$ 和 $t=1$ 检查原方程；若写成 $t(2,0)+(-1,1)$，代回即发现不对。
不把这段复算经历写成“已完成校验”，把学生确实需要的一步代回演示写出来。

## 4. 用案例与图说明同一个数学关系

现实案例连起变量/单位/数据来源/模型/结果解释；模拟量明确是假设，不冒充近年统计。
缺资料就精确报告需要什么，不能造新闻或只插一页“近期资料已满足要求”。
几何图应指出每个轴、点、方向或变换对应哪个数学对象，再安排学生观察与代数对应。
直线交点/投影/二维变换用项目计算图，其他题材先选可验算的工具；不手填图形像素。

## 5. 学生注意力的删除反事实

逐句问删去会损失什么当前理解。先修/核心/时长、TXT行号、孤立引文、方法口号、
无上下文的“不是地理位置”没有天然保留权。结论说“同一组数要满足每个方程”，
不要只写“同时满足，分别论证”。

“假设设备功率在记录期间保持不变”解释模型，可保留；“教学假设已符合要求”是制作说明。
“这些数值是模拟，不是实测”可防止错误现实推断；不必用整页向制作者道歉或请求资料。
规范术语不等于把所有“定义”换成“知道”，学生仍需理解准确含义。

## 6. 固定表达工具

只用受限 Markdown、数学和外部图片。标准图片单独成段，图注另段；表格边框由全局主题提供。
内容过多就删冗余、拆宽表/推导/例题，不改 CSS、局部 class、HTML、图片尺寸或 TeX 缩字。
用 `assets/<unit-id>/` 避免跨课同名冲突。项目计算图修改 .plot.json 后重新生成，不手改 SVG。
提交前在实际输出目录运行 `mpres source check`；报告失败就修确切源稿，不声称工具已通过。

## 7. 只提交本次真实结果

summary 写完成的数学与教学内容；feedback_checks 对实际 id/version 引用真实页内片段。
必要教学安排、未解决资料或授权问题放 teaching_notes/open_questions，不成为学生页面。
没有 downstream PDF/审核回执不能宣称完成；也不要为凑检查证据另造“本课使用规范术语”页。
收到 submission_correction 时按其精确错误保留正确稿件，仅修源规约/字段问题；
不是重新设计课程、改变 runtime 或让 reviewer 验收你的修复。
