# Marp authoring standard

- One canonical `presentation.md`; PDF is the only generated presentation artifact.
- Titles are used when they orient the learner, not as compulsory decoration. Avoid slogans and vague humanities-style filler.
- Continuous exposition may rely on neighbouring slides; stronger local self-containment is required at lesson openings, after activities, on example continuations, and where objects or assumptions are easy to confuse.
- Reuse one concrete mathematical object across a terminology cluster when that helps learners connect definitions.
- State the object, space, dimension, quantifier, condition, unit, or causal link before a summarising slogan.
- Calculation slides explain why the method is chosen and what the result means.
- Prefer native text/formulas, Markdown tables, theme CSS, simple SVG, and approved existing resources before Python figures. Never draw a table with a plotting library.
- Every course content unit contains 2–3 diagnostically useful multiple-choice questions. Academic reports are exempt.
- Exercise prompts and answers occupy adjacent separate slides and are paired in the manifest.
- No screenshots, persistent HTML, remote images, or model vision.
