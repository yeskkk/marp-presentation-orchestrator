# 语义指导的源码维护

本文件供维护者使用，不注入 planner、author 或 reviewer 的运行输入。

## 从反馈提炼原则

先识别历史问题暴露的职责、判断或工具边界，再写成不依赖课程题材的原则。
具体事故原文和复现场景保留为测试素材，不能直接成为所有任务的必读规则。
工具能力与权限属于代码及接口文档；任务的特定要求仍留在真实 TASK 和反馈中，不为通用化抹掉用户原意。

## 核对职责与方法

每个角色需说明判断目标、输入、工作顺序、证据限制与结果。五个 reviewer 各有完整方法，
但仍共用原 specialist-reviewer agent 与 reviewer runtime。审查是否越权包办别的通道，
是否将多条流程纠缠为一次工作，是否引入多余调用或过程文件。

## 回归材料与边界

[测试素材](../../tests/fixtures/semantic/README.md) 与实际路由、schema、输入顺序和状态转换测试一起维护。
没有模型执行就不声明教学质量已实测；不能用篇幅、标题数量、词语黑名单或 skill lint 代替审读。
程序测试只检查真实接口与行为，例如选到正确指南、维护素材不被加载、旧会话不重复 TASK。
