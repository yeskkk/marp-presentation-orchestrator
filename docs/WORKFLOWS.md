# 分流程工作手册

本手册按“当前在做什么”组织，不按版本补丁排列。执行事实来自数据库，教学判断来自
已确认任务、明确用户反馈和本次 job。身份/版本/回执由程序生成，不另抄一套过程文件。

## 任务上下文只建立一次

启动后先确定用户要新建、修改还是继续，不自动开工。main 和手动角色在任务与当前方向
确定后，开始实质工作前完整读一次 TASK.md；不能以角色指南代替用户意图。
已读的同一会话直接复用，只应用后续明确变更，不因换 job、纠错、分段试读重复全文阅读。

runner 将精确确认文本放入首个语义请求的 `task_context`，阅读顺序为任务→角色指导→
本次工作与反馈→内容。正常有历史反馈时是已有 brief，没有反馈时是已有 run 或首个
 audience_step；不新增一次模型调用。TASK 不放进按需附件、不截断，全文计入既有预算。
成功的真实回执会记下本 session 的上下文接收记录；以后只传 `reuse` 提示，不重发全文。
这是对宿主执行协议的记录，不是证明模型理解了任务，也不是让模型写另一份“已阅读”报告。

runner 重启不会清空记录。新真实会话需要自己读一次；旧版在途请求不追溯造阅读记录，
其下一次新请求建立上下文。`apply_delta` 仅针对已有正式配置版本变更；它不提供新授权
或跳过确认的入口。会话上下文真的丢失时应如实对账，不能伪称记得；当前 runner 不自动 reset。


## A. 新课程生产

**入口条件：** 尚无确认的任务，或用户明确要新建；不是修订已交付 p01。
main 读取实际可访问的资料，整理受众、证明深度、问题入口、例题和课次边界。
每课 brief 是工作说明，不是标题页；学生页不承载时长、先修、核心标签和制作检查。
程序展示后等用户确认，随后 materialize 从计划生成 job。遇到确认前语义冲突要说明，
不要拿旧文档里的“保留全部证明”覆盖用户已经明确的少证明要求。

runner 领取写作 job，先 brief 再 run。合格单元组装，短时 editor 处理跨课衔接。
full gate 通过才冻结，然后五通道首次审核。无 finding 可发布；有 finding 则作者
在原稿上修正，逐项 resolutions，机械再检后发布；needs_decision 停在明确待决。
没有常驻 coordinator、六阶段人工交接或作者自报“gate_passed”。

**完成／停止：** 正式 PDF commit 后目录 materialize；ready 才交付。
all 可继续；pilot 首稿和 each 每稿等待真实用户许可。不要把下游尚未执行写成作者已完成。
当前代码对 feedback issue 的拦截仍较严格；证据缺口据实报告，不能为推动流程伪称 satisfied。

## B. 延续已有 compact 任务

**入口条件：** `tasks/<slug>/.mpres/task.sqlite3` 存在，选择该任务并核对三份入口。
先 task status、runner outstanding，再观察真实宿主能力。数据库升级不增加教学、runtime
或预算授权；配置不一致不能靠重写 snapshot 消除。已有 output 可能含未提交作者修改，
不能重新拷贝旧稿覆盖它。

没有不确定回执时让 runner 沿状态机继续。外部执行不明走 E，不当作失败重写新稿。
旧页面用旧主题是历史事实；新副本用项目主题，旧 gate 不证明新副本通过。

## C. 已发布稿 review-first 返修（少走弯路的旧稿改良路径）

**入口条件：** 指定课件有真实发布记录，处于允许开返修的交付边界。
`repair open --mode review-first` 仅建立只读问题展开；指定目标可以一份或一批。
诊断从提供的代表性证据说明问题定义、变体、相似问题、非目标、验收和资料缺口，
不能声称未读目标都已审查。展示 proposal 的准确版本、目标发布修订和删页权限。
用户的初始投诉不等于批准模型展开的全部范围；修改 proposal 后重新展示、确认。

确认后五通道直接看原已发布修订，**不先 edit，也不重写各课次草稿**。
原稿可能不符合新源码规约，这是审核对象而非新 gate 通过证据。
随后作者接原稿＋本轮 findings＋confirmed repair scope，自修和复算；新修订必须过当前机械 gate。
本模式即使首次无 finding 也会创建作者修订，不将旧稿原样冒充新版交付。

启用并确认 allow_slide_changes 时，可删无用页、合并重复页。消失原 ID 必须有累计
slide_changes，合并目标保留；没删的页保留 ID，不能全稿重命名规避对应关系。
后续 gate 修正仍针对同一返修基线和剩余问题，不把已经改好的内容退回原稿。

**出口：** 交付新 PDF/Markdown/资产目录，历史版本不动，恢复原 pilot/each 暂停。
不新增作者修复后的语义验收 reviewer，不顺手开未指定的 p02。

## D. edit-first 返修（明确选用的另一条路径）

开案、只读展开、方案展示和用户确认与 C 相同，但 `mode=edit-first`。
确认后先由作者根据问题族编辑，full gate 合格再首次五通道审核，必要时作者修订。
适用于用户明确要先完成改写再审的任务；不是 review-first 前的额外阶段。
系统默认保留此兼容选项，文档不应把两条模式混成三轮审核。

## E. 机械错误、证据缺口与不确定执行

| 已知事实 | 正确处理 | 禁止 |
|---|---|---|
| 某稿检查报告真实内容错误 | 原稿与精确错误送作者，在既定预算内修正 | 修改 theme/放宽 HTML 来过门 |
| 合法 receipt/runtime/usage 已收到，但作者结果字段或源码违规 | 记录失败，新 attempt 有界纠正 | 宣称原调用从未发生，丢掉用量 |
| 已识别短时浏览器/子进程故障 | 同稿 read-only gate 重试，独立工具预算 | 消耗语义修稿额度、要求作者破坏正确公式 |
| 未知 create/run 结果或 live inventory 冲突 | 保留 uncertain，核对真实宿主证据 | 重复启动、假 handoff、假关闭 |
| 资料缺口/权限/范围/语义冲突 | 说明具体缺口及影响，交 main/用户决定必要变更 | 把猜测或无关案例塞进学生页交差 |
| 环境已修好，重跑发现内容错误 | retry-checks 回原阶段，作者自修 | 将失败报告改成通过 |

实现的自动纠正并非覆盖所有 reviewer 引用错误和外部适配器错误。未支持的恢复应明确报告，
不能在文档里写成“都会自动修好”。本手册不新增自动授权、无限重试或隐式模型切换。

## F. 导入旧文件制任务

只读 import-legacy 到新 slug，保留来源目录。导入源码是未验收 artifact，句柄不视为活跃，
旧 gate 与旧模板流程不继承。补齐真实课次 brief、现行教学选择和资料路径后重新呈现确认。
已是 compact 的 v7 任务一般直接按 B/C 恢复，不要因版本号旧再导入一遍。
备份 DB 只覆盖 DB；迁移实验在副本上，实际内容和发布文件必须另行保全。

## 共同不变量

固定 runtime、固定版式、真实回执、首轮五通道独立性、原修订不被覆盖、学生与制作信息分离。
调整指令文档不会追认历史 review 使用了新规范，也不自动改旧任务的三份配置。
