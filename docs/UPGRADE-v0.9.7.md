# v0.9.7 重建版：升级与继续返修

## 使用哪个包

使用 `marp-presentation-orchestrator-v0.9.7-rebuilt-source.zip`。这是从用户上传的
v0.9.6 正确源码增量制作的累计版，替代此前被拒绝的同号包。版本字段保持 `0.9.7`，用包名、
本文件和随附 SHA256 区分重建版。无需逐版安装。

本版保留 v0.9.6 的活动 skill、数学表达/标题/分行规则、作者处理全部有效审核问题的职责、
单页练习约束、编拟算例原则、当前版本清理与恢复、自动维护策略及旧任务接续。

## 1. 安全更新

先确认没有活动模型执行或清理操作，保存一次可回退的完整备份。保留现有 `tasks/`、教材、
资产、任务数据库、配置、实际交付与本机环境；不要用新包中的空目录覆盖它们。
备份是迁移退路，不应每轮永久累积。

若工作区来自正确的 v0.9.6，可在 Git 工作区先检查随附增量补丁：

```bash
git status --short
git apply --check /path/to/marp-v0.9.6-to-v0.9.7-rebuilt.patch
git apply /path/to/marp-v0.9.6-to-v0.9.7-rebuilt.patch
```

该补丁相对于所提供的 v0.9.6 精确文件生成。检查发生冲突时应核对本地修改，不跳过冲突，
不以旧 v0.9.3 或已被拒绝的 v0.9.7 代替基线。也可使用完整源码包同步程序文件。

已经覆盖过被拒绝的 v0.9.7 工作区，不宜只把本补丁硬套上去。应以正确 v0.9.6 或本重建包
恢复完整的受版本控制源码，再保留/合并自己的任务和配置，排除旧错误包遗留文件。
不要对含用户任务的工作区直接执行全目录清空命令。

## 2. 旧任务检查与兼容

在项目根目录运行：

```bash
bash start.sh --cli task open linear-algebra-v7
bash start.sh --cli task status linear-algebra-v7
```

启动器需要本机已有的项目依赖；自选已装依赖的解释器可显式设置 `PYTHON_BIN`。
Windows 使用对应 `start.ps1` / `start.cmd` 的同一参数。

必要时自动迁移到 schema 14，新增成本归属及观测状态表，保留旧 schema 13 的检查点关系。
首次打开不重新规划、不创建空任务，也不改写授权或模型强度；重复打开应幂等。
迁移后不要让 v0.9.6 再向同一数据库写入；回退使用迁移前一致的完整备份。

当前任务应识别五稿：p01-01、p01-02、p02-01、p02-02、p03。
旧父稿 p01/p02 不重新成为制作目标；`p03 -> p03` 是原位保留，不是已替代父稿。
有未决执行先对账，不通过删除日志、清库、改 accepted 状态或重新调用模型消除它。

打包归档若缺 PDF，程序如实报告并阻塞普通交付；不能假造成功。归档维护所用
`allow_missing_pdf` 不是生产免检，现场正常文件完整的任务不需要这个例外。

## 3. 继续整稿表达返修

```bash
bash start.sh --task linear-algebra-v7
```

接续时向 main 明确五稿当前返修目标即可，不需要新建任务。例如：

> 以 p01-01、p01-02、p02-01、p02-02、p03 当前交付为基线，做整稿表达返修。
> 检查全部学生可见文字：无帮助的标题直接删；使用正常、准确的数学表达；独立句子分别
> 起行；解释明白晓畅、自然连贯，不增加俏皮口号。保留单页独立练习和现有教学边界。
> author 同时处理五通道发现的其他有效问题，不能只因不在最初重点中而忽略；超出已授权
> 课件或涉及权限/教学范围变更的问题交 main 决策。不启动 p04–p08，不重新拆分已完成的
> 课件，不自动增加作者自修后的审核轮次。

按既有确认/返修契约执行。软件升级不是课件语义返修，也不把历史“通过”改成满足新标准。

## 4. 统计本轮用量

`--case` 使用实际返修案 ID，不是任务名。可从任务状态或未筛选 JSON 报告查看已记录归属。
新返修应使用新建的实际 ID，不沿用下面的历史 ID。

```bash
bash start.sh --cli report usage linear-algebra-v7 --format md
bash start.sh --cli report usage linear-algebra-v7   --case repair-4822efd283054c51b4a55f813b8455d1 --format md
bash start.sh --cli report usage linear-algebra-v7   --presentation p03 --since 2026-09-15T00:00:00+08:00   --until 2026-09-16T00:00:00+08:00 --format csv --output p03-usage.csv
```

也可加 `--batch BATCH_ID`。各条件取交集。时间带时区，until 不含边界；完整调用按开始时间
选入，不按分钟比例拆分 token。输出文件已存在时程序拒绝覆盖，请使用新的文件名。
报告为只读操作，不迁移旧库、不重建索引、不调用模型。

历史未归属记录保持未知，不能按今天 deck 的状态回填。自动等待只说明程序观测，未闭合
区间时长未知，旧空档不猜原因。缓存输入不可加在输入之上；没有账单证据不计算金额。

## 5. 清理与恢复

保留 v0.9.6 的完整维护流程，见 [STORAGE-MAINTENANCE.md](STORAGE-MAINTENANCE.md)。
清理不是返修前置步骤。使用当前交付检查点和明确的策略，先预览、确认，再应用对应计划；
不要直接删历史目录或让模型逐条决定 SQL。自动安全点收尾仍需原有显式策略。

本版清理后的成本归属不依赖完整旧提示词；保护精简账本，保留 tombstone 的已清理请求
拒发规则。清理中断按已有恢复步骤完成，不重发历史请求。

## 6. 能力和验证边界

有界滚动调度用于 Codex bridge；command-adapter 沿用原逻辑。观察到一个真实回执后可以
接续独立后继，仍服从容量和授权。拒收或未知执行停止新增派发，但收取已发请求的真实结果。
`--cycles` 限制准入 tick；不是运行分钟数，也不是整批次数。

随附验证包含原 v0.9.6 测试、增量测试及用户归档隔离副本；没有调用真实模型改写五稿，
未替代原生 Windows、真实 Codex 权限和本轮浏览器/PDF 环境验收。不承诺未经实跑的 token
节省比例。完整基线差异、测试日志及源码哈希见交付验证材料包。
