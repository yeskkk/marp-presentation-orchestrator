# 如何维护指南而不再次变成补丁堆

## 1. 先定位所有者

教学判断改对应六个 skill；机器约束改源码和测试；宿主协议改 HOST-PROTOCOL；
正常/返修/恢复/迁移步骤改 WORKFLOWS；新任务输入改三份 compact 模板。
同一规定只维护一个正文来源，其他地方用精确链接或路由，不复制四段给每个角色。

## 2. 文档结构

技能正文按用途、输入、判断顺序、正反例、输出、权限/停止边界组织。
条件性小节使用稳定二级标题 ID，供 guidance.py 选择。新增/重命名小节同时改路由和测试。
不要在文件尾不断追加“最新版优先于旧版”；删除或整合冲突句，历史说明留 changelog/legacy。
README 解释整体结构与每步怎么运作，更新说明只在末尾。

## 3. 与代码一致

指南不得让 reviewer 改稿、author 管审核、诊断自动确认、main 健康轮询，或 runtime 动态升降级。
允许读资源不等于已读；当前没有的 provider/恢复能力写成限制，不提前声称支持。
新请求会用当前指南，在途请求继续按已派发包与真实回执对账；升级代码不能追认旧审核读了新规范。
本阶段未改用户确认配置/反馈内容，不新增 DB 表或语义 schema。

## 4. 发布前检查

1. 本地链接、当前/兼容模板边界、CLI 示例用真实解析器检查。
2. 所有 route 的 fragment 都存在、非空、只有目标通道；没有 fallback 到半套旧指南。
3. schema 样例用实际验证器；页内引用/attention 索引取真实样稿，错误样例必须失败。
4. 跑完整回归和独立解压包；保留 legacy 的109个模板原字节，不能靠删回归通过。
5. 对涉及教学判断的规则，记录明确正反例供真实模型校准；静态关键词断言不等于质量实验。

所选指南字节计入已有 context_budget_bytes，不能静默截断，也不为加说明擅自提高任务预算。
测试量化初始文本字节，不将它宣传成真实 token/费用降低。
